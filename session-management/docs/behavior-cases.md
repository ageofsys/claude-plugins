# Behavior Cases — session-management

`session-start` / `session-end` 의 행동 계약을 *수동 회귀 검증* 가능한 형태로 적어 둔 자료. 자동 eval 도입 전 단계의 가벼운 안전망.

목적은 두 가지다:
1. **트리거·안티패턴·degradation 의 의도된 동작을 명문화** — SKILL.md 만 읽고는 놓치기 쉬운 *경계 사례* 를 기록.
2. **변경 시 회귀 검사 기준** — SKILL.md 의 trigger / step / anti-pattern / degradation 섹션을 손대면 이 문서의 해당 케이스를 함께 갱신해야 한다.

CLAUDE.md 와 함께 읽을 것. 새 케이스는 발견되는 대로 추가한다.

## 1. 트리거 케이스

### 1.1 명확 — 즉시 진입

| 발화 | 기대 동작 |
|---|---|
| "세션 시작" | `session-start` 즉시 진입, 6단계 수행 |
| "오늘 세션 시작" | 동일 |
| "이전 세션 이어서" | 동일 |
| "어디까지 했더라" | 동일 (직전 작업의 메타 질문으로 해석) |
| "where did we leave off" | 동일 |
| "pick up where we left off" | 동일 |
| "세션 종료" | `session-end` 즉시 진입, 7단계 수행 |
| "세션 마무리" | 동일 |
| "세션 끝" | 동일 |
| "wrap up the session" | 동일 |
| "let's wrap up" | 동일 |
| "이번 세션 정리" | 동일 |

### 1.2 모호 — 단일 확인 질문 후 진입

| 발화 | 직전 컨텍스트 | 기대 동작 |
|---|---|---|
| "이어서 가자" | 직전 발화에 **활성 작업** (코드 변경 직후, 빌드 실행 중) | 한 줄 확인: "이전 세션 이어서 시작할까요? / 지금 작업 계속할까요?" — 사용자 응답에 따라 진입/스킵 |
| "이어서 가자" | 첫 발화 또는 직전이 비어 있음 | 즉시 진입 (다른 해석 없음) |
| "오늘은 여기까지" | 직전 발화에 **진행 중 작업의 정리 신호** ("마지막 커밋 정리하고", "내일 이어서") | 즉시 진입 |
| "오늘은 여기까지" | 정리 신호 없음 | 한 줄 확인: "세션 종료 wrap-up 진행할까요? / 잠깐 자리 비우는 건가요?" |

### 1.3 트리거 금지 — 즉시 거절 또는 무관 처리

| 발화 | 사유 |
|---|---|
| "시작하자" 단독 | 너무 광범위. 세션 단위 의도 부재 |
| "정리해줘" 단독 | 너무 광범위. 코드/문서 정리일 수 있음 |
| "시작" 단독 | 단어 1개로 의도 추정 불가 |
| "끝" 단독 | 단어 1개로 의도 추정 불가 |
| 코드 작성/수정 요청 (트리거 키워드 없음) | 두 스킬 모두 비활성 |

### 1.4 사용자 의도 우선 — 부분 진입

| 발화 | 기대 동작 |
|---|---|
| "세션 시작하고 P14 부터" | 6단계 중 1~3 단계 요약은 출력 (컨텍스트 보존) → P14 작업 진입 |
| "세션 종료, push 까지 부탁" | 7단계 진행 + 마지막에 push 의사 확인 후 실행 |

## 2. 안티패턴 케이스 (절대 하면 안 되는 동작)

### 2.1 자동 비가역 작업 금지

| 안티패턴 | 올바른 동작 |
|---|---|
| `git commit -m ...` 자동 실행 | 커밋 메시지 *제안* 만, 사용자 동의 후 실행 |
| `git push` 자동 실행 | push 의도 명시 시에만, 동의 후 실행 |
| `docker compose up -d` 자동 실행 | "실행할까요?" 단일 질문 → 사용자 confirm 후 |
| `npm run dev` 등 dev server 자동 기동 | 동일 — confirm 후만 |
| `/rename <name>` 시도 (tool 호출 또는 슬래시 명령으로) | 출력은 *문자열 1줄* 로만 — 사용자가 수동 실행 |
| `git_state` 에 placeholder/빈 값 강제 주입 (비-git인데) | 블록 자체를 생략 — 값을 지어내지 않음 |
| 분기 감지 시 `git checkout` / `cd` 자동 실행 | 제안 문자열만, 실행은 사용자 |
| detached HEAD 에 `git checkout` 제안 | 금지 — "detached 상태" 주의만 |

### 2.2 영구 자원 삭제 금지

| 안티패턴 | 올바른 동작 |
|---|---|
| SQS queue 자체를 `delete-queue` | queue 안의 *test 메시지* 만 `purge-queue` |
| S3 bucket 자체를 `delete-bucket` | bucket 안의 *임시 파일* 만 삭제 |
| 영구 git branch (`main`, 공식 feature branch) `branch -D` | 임시 작업 branch 만 삭제 — 영구 branch 는 절대 X |
| 메모리 디렉토리 자체 삭제 | 단일 메모리 파일만 인덱스에서 제거 |

### 2.3 강제 생성 금지

| 안티패턴 | 올바른 동작 |
|---|---|
| `PLANS-INDEX.md` 가 없으면 자동 생성 | 스킵, 보고만. 사용자가 명시하면 그때 생성 |
| `CHANGELOG.md` 가 없으면 자동 생성 | 스킵 — 가능하면 생성하지만 강제 X |
| handoff 노트가 없으면 마지막 git log 로 합성 | 스킵, "핸드오프 없음, MEMORY.md 만 참조" 보고 |

### 2.4 정보 조작 금지

| 안티패턴 | 올바른 동작 |
|---|---|
| PLANS-INDEX 와 핸드오프 불일치를 사용자에게 숨김 | 두 후보 모두 표시 + 사용자 선택 요청 |
| 메모리를 무비판적으로 인용 (1~2주 지난 내용) | 의심되면 코드/git 으로 *검증 후* 인용. stale 발견 시 수정 |
| session-end 가 정리한 임시 자원을 session-start 에서 자동 재생성 | 빈 상태 가정으로 시작 — 재생성 X |
| 추천 세션명을 "현재 세션명" 처럼 표시 | "지난 핸드오프 추천명" 라벨로 표시 — 실제 `/rename` 실행 여부 미확인 |
| `git_state` 불일치를 브리핑에서 숨김 | ⚠️ 명시 + 제안 문자열 노출 |
| commit-only 불일치를 "정상" 으로 뭉갬 | ancestry 4분류로 신호 보고 (`정상` 라벨은 worktree+branch 모두 안전할 때만) |

### 2.5 보고 누락 금지

| 안티패턴 | 올바른 동작 |
|---|---|
| "세션 시작했습니다, 무엇을 할까요?" 만 출력 | 1~6 단계 결과 표 + 제안 시작점 출력 |
| "마무리 작업 시작합니다" 만 출력하고 멈춤 | 1~7 단계 진행 후 결과 보고 |
| 단계가 모두 ❌ 라도 침묵 | 브리핑/요약은 항상 출력 — 빈 상태도 *상태* |

## 3. Graceful Degradation 케이스

### 3.1 session-start

| 환경 | 영향 단계 | 기대 동작 |
|---|---|---|
| `MEMORY.md` 없음 | 1, 5 | 보고 ("메모리 인덱스 없음 — 첫 세션") + 강제 생성 X |
| 핸드오프 파일 없음 | 1 | 보고 ("핸드오프 없음, MEMORY.md 만 참조") + 강제 생성 X |
| 핸드오프 frontmatter 없음 또는 `recommended_session_name` 부재 | 1, 6 | 추천명 줄 생략, 본문 회수는 그대로 |
| 비-git workspace | 2 | 스킵 보고 ("git 저장소 아님 — 정합성 비교 생략"), 다른 단계 계속 |
| `git` 명령 실패 | 2 | ⚠️ 보고, 사용자 점검 권고, 다른 단계 계속 |
| `PLANS-INDEX.md` 없음 | 3 | 스킵 ("PLANS 미사용 — 핸드오프 기준") + 강제 생성 X |
| CLAUDE.md 인프라 명령 미명시 | 4 | 일반 점검만, 모호하면 ⚠️ 사용자 확인 |
| `docker` / `lsof` 없음 | 4 | 스킵 ("점검 도구 없음") |
| 메모리 디렉토리 자체 부재 | 5 | step 1 결과 재사용, 환기할 항목 없음 보고 |
| 모든 단계 ❌ | 6 | 한 줄 브리핑이라도 항상 출력 |
| `git_state` 블록 부재 (0.3.0 구버전 핸드오프 — git repo는 존재) | 2 | legacy 모호 비교 fallback + "git_state 없음 — 정합성 대조 생략" 보고 |
| `git_state` 일부 필드 부재/파싱 실패 | 2 | 해당 필드만 "대조 불가" 보고, 나머지 필드는 정상 대조 (블록 전체 fallback 아님) |
| worktree_root 3조건 검증 실패 (경로없음/git -C 실패/결과≠저장값) | 2 | `cd` 제안 없이 "현재 머신에 없음/worktree 확인 실패" 보고 |
| branch 불일치 | 2 | ⚠️ + `git checkout <stored branch>` 제안 문자열(비실행) |
| branch = (detached:…) | 2 | `git checkout` 제안 금지 + 브리핑에 "이전 세션 detached 상태" 주의 |
| stored commit 로컬에 없음 | 2 | ⚠️ 미-fetch/다른 머신/다른 repo 가능 |
| stored commit 이 현재 HEAD 의 ancestor | 2 | 정보: 이후 N commits 진행 (정상 경로) |
| 현재 HEAD 가 stored commit 보다 behind | 2 | ⚠️ stale checkout/미-pull |
| stored commit 과 diverged | 2 | ⚠️ force-push/rebase/분기 가능성 |

### 3.2 session-end

| 환경 | 영향 단계 | 기대 동작 |
|---|---|---|
| 비-git workspace | 1, 4c | 1: 스킵 보고 ("커밋 단계 생략"), 다른 단계 계속 / 4c: `git_state` 블록 통째 생략 (강제 빈 값 금지) + "git_state 생략(비-git)" 보고 |
| `git` 명령 실패 | 1 | ⚠️ 사용자 점검 권고, 다른 단계 계속 |
| 메모리 디렉토리 없음 | 2, 4, 6 | `mkdir -p` 후 진행 (생성) |
| 디렉토리 생성 실패 (권한) | 2, 4 | ❌ 인메모리 보고만, 디스크 저장은 사용자 권한 해결 후 수동 |
| `PLANS-INDEX.md` 없음 | 3 | 스킵 ("PLANS 미사용 — 단계 생략") + 강제 생성 X |
| 핸드오프 파일 쓰기 실패 | 4c | ⚠️ 인라인 표시는 유지, frontmatter 추천명을 사용자에게 직접 노출 |
| 백그라운드 프로세스 추적 정보 없음 | 5 | 스킵 ("BG 없음") |
| 외부 자원 접근 실패 (AWS/cloud) | 5 | ⚠️ 사용자 결정 위임, 자동 재시도 X |
| `MEMORY.md` 없으나 메모리 파일은 있음 | 6 | 인덱스 신규 생성 (한 줄/파일) |
| 메모리 디렉토리 자체 없음 | 6 | 스킵 (step 2/4 결과에 의존) |
| step 4c 실패로 frontmatter 추천명 부재 | 7 | 4b 의 인메모리 후보 사용, 다음 세션 자동 회수 못 함을 명시 |
| 사용자가 이미 `/rename` 한 흔적 | 7 | 스킵 + "이미 명명됨" 보고 |
| detached HEAD | 4c | `branch: (detached:<sha7>)` 로 기록 |
| dead-end 없음 | 4a | `## 시도했으나 안 된 것` 서브섹션 통째 생략 |

## 4. 회귀 검사 절차 (수동)

SKILL.md 의 trigger / step / anti-pattern / degradation 섹션을 손대면:

1. 이 문서의 해당 표(1~3절)를 함께 갱신
2. 새로 의도된 케이스를 추가, 폐기된 케이스를 제거
3. SKILL.md 와 이 문서가 *같은 의미*를 표현하는지 한 번 정독

자동 eval 은 도입 보류 (P2). 도입 시 이 문서가 *케이스 데이터의 출처* 가 된다.
